# Interface languages

English (`en`) is the default. English and Vietnamese (`vi`) choices appear only
inside the user avatar menu, including on mobile. A check marks the active
language. The saved preference continues to apply after signing out.

The `mindbridge-locale` cookie saves the choice for one year. The server reads it
for the initial document language, metadata, and rendered interface. Unsupported
cookie values fall back to English. Existing URLs and authentication callbacks
are unchanged.

Switching updates the React context and `<html lang>` in place. It does not reload,
navigate, or restart a voice session. Companion names, topics, transcripts, and
voice/tutor language settings keep their original values. Subject and voice
filter identifiers also stay unchanged; only their display labels are translated.

## Adding interface copy

English source text is the fallback catalog. Add its Vietnamese translation to
`lib/i18n/vi.json`, then use one of:

- `<LocalizedText>Interface text</LocalizedText>` for text in server or client JSX.
- `const { t, locale } = useI18n()` in client components, and `t("Interface text")`
  for string props, labels, and known error messages.
- `getLocale()` and `translate(locale, text)` for server-only strings such as metadata.

Translate app labels, not user content or stored enum identifiers. Date formatting
uses `en-US` or `vi-VN`. Clerk authentication/account controls use the corresponding
built-in Clerk localization.

Run `npm run test:i18n`, `npm run test:auth`, `npm run test:companion`, and
`npx tsc --noEmit` when changing language behavior. The catalog test checks static
translation calls and JSX labels for missing Vietnamese entries.
